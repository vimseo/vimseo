    Global sensitivity analysis: Morris and HSIC¶

    The :class:~.SensitivityTool ranks the inputs of a model by their influence on its outputs over a whole parameter space, with the Morris or the HSIC method. It either samples the model itself or uses the samples of a DOE prepared in advance. BendingTestAnalytical is used to illustrate the use of this tool.

    For a local analysis around nominal values, see the One-factor-at-a-Time example.

    The last section, with runs archived in MLflow, needs the mlflow extra.

    Using the SensitivityTool¶

    The tool samples the model over the parameter space and computes the sensitivity indices through the GEMSEO API. The settings of the analysis are:

    • sensitivity_algo: the sensitivity method, either "MorrisAnalysis" (default) or "HSICAnalysis",
    • n_replicates: for the Morris method, the number of One-factor-at-a-Time trajectories, each one starting from a random point; along a trajectory, each input varies in turn, the previous ones keeping their new values,
    • n_samples: the number of samples; if 0, it is deduced from the method, e.g. n_replicates times the number of inputs plus one for Morris.
    output_names = ["reaction_forces", "dplt_at_force_location", "maximum_dplt"]
tool = SensitivityTool(working_directory="sensitivity_tool_results")
tool.execute(
    inputs=SensitivityToolInputs(
        model=model, parameter_space=space_tool.parameter_space
    ),
    settings=SensitivityToolSettings(
        output_names=output_names, sensitivity_algo="MorrisAnalysis", n_replicates=5
    ),
)
tool.save_results()
print(tool.result)

    The Morris indices are, for each output and input component, statistics of the elementary effects of the input over the trajectories:

    • mu: their mean,
    • mu_star: the mean of their absolute values, which measures the influence of the input,
    • sigma: their standard deviation, which reveals non-linear effects and interactions,
    • relative_sigma: sigma divided by mu_star,
    • min and max: the extrema of their absolute values.

    Using the samples of a DOE prepared in advance¶

    The samples can be computed beforehand by a :class:~.DOETool, for instance on a cluster, and then its result is passed to the :class:~.SensitivityTool as doe_result: the model is not executed again. This result records the DOE algorithm, which the tool checks.

    For a Morris analysis, the DOE must be generated by the DOE algorithm "MorrisDOE", whose n_samples is the number of replicates times the number of inputs plus one. Its settings are passed through algo_settings, here the relative step of the trajectories in the unit hypercube.

    n_replicates = 5
doe_tool = DOETool(working_directory="morris_doe_results")
doe_tool.execute(
    inputs=DOEInputs(model=model, parameter_space=space_tool.parameter_space),
    settings=DOESettings(
        output_names=output_names,
        algo="MorrisDOE",
        n_samples=n_replicates * (space_tool.parameter_space.dimension + 1),
        algo_settings={"step": 0.05},
    ),
)

    The HSIC indices rank the inputs. The analysis also tests, for each input and output, the hypothesis that the output is independent of the input. A p-value below a significance level, e.g. 5%, rejects this hypothesis: the input is influential.     Using runs searched in an MLflow archive¶

    The samples of a HSIC analysis do not have to come from a DOE: any dataset of runs can be passed as dataset, e.g. runs gathered over several studies and searched in an archive, as long as its input samples are independent and distributed according to the probability distribution of the inputs. Here, the runs are archived in MLflow, in the study "hsic_samples", i.e. the MLflow experiment of this name (see the examples of the data management). The archive of a previous execution of this example is deleted, and the model cache is disabled so that every point of the DOE is run and archived:
